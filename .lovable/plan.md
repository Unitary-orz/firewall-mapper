# SNAT 修正并接入访问关系

## 目标
让源 NAT 按真实语义呈现“原始来源 → 源地址转换 → 原目的 → 服务 → 命中策略”，不把服务或转换后源地址误当成目的。

## 修改内容
1. **修正 SNAT 解析**
   - 按 `接口 / 原始源 / 原目的 / 服务 / 转换后源（或 interface）/ ID` 读取。
   - 将服务写入 `origDstService`，将 `interface` 或地址池正确写入源转换字段。
   - NAT 列表同步显示服务、转换后源；出接口规则显示实际接口地址。

2. **建立 SNAT 策略关联**
   - 只用启用且未过期的 SNAT 和有效策略生成访问路径。
   - 按原始源、原目的、服务的真实包含或重叠关系匹配策略，`any` 可通配。
   - 转换后源地址不参与策略匹配；路径状态仍由策略的 permit / deny / 未关联决定。
   - 等价的 SNAT 与 Direct 路径去重，保留范围更大的真实直连路径。

3. **接入现有五段式访问关系**
   - 第二段新增 SNAT 标签：主图简短显示“SNAT 源 → 转换后地址 / 出接口地址”。
   - 悬浮或点按显示规则编号、原始源、转换后源、目的、服务、接口和日志。
   - 来源、目的、服务和策略继续复用现有预览；手机端保持纵向布局。

4. **验证**
   - 增加解析与关联测试，覆盖出接口、地址池、服务、`any`、禁用及重复 Direct。
   - 用真实配置验证 SNAT #274：源为「数据服务管理子系统」、目的为 `59.225.204.3`、服务为 `59.225.204.3-8160 / tcp/8160`、源转换为 `172.23.51.138（ge0/0）`，关联策略 #300。
   - 检查桌面悬浮、手机点按、候选筛选和“隐藏未关联策略”。

## 技术范围
主要修改 `src/lib/parser/index.ts`、`src/lib/access.ts`、`src/components/access/FocusRows.tsx`、`src/routes/nat.tsx`，并新增针对性测试；不改变 DNAT 的现有匹配语义。
